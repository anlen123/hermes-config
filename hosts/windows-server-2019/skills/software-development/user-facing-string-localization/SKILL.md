# 用户可见文案（UI / 聊天面）汉化与验收

## When to Use（触发场景）

- 系统提示词/词典已汉化，但**用户在实际界面或聊天窗口仍看到英文**
- 用户反复抱怨「怎么还是英文」「都几轮了没汉化完」
- 首次接手一个「已经做过一轮汉化」的应用，需要弄清楚还差哪些面
- 刚翻完一批文案，需要独立验收（而不是靠子代理或自己的一句「我翻了」）

> 承下：AST 跨度替换、f-string 重建、pristine 副本与回滚机制那套**机械层**在兄弟 skill
> `upgrade-safe-source-patching`（该 skill 为用户所有、不可自动改）。本 skill 只管
> 「翻哪些面、怎么并行翻、怎么验收才算完」。

## 核心判断：i18n 词典 ≠ 已汉化

**i18n 层只覆盖「被包装过」的串**（`t(...)` / `_()`）。大量硬编码串根本不在词典里，
走 i18n 永远翻不到。用户反复说「怎么还是英文」时，几乎必然是这条：前几轮只补了
`locales/`，而他在界面上看到的是散落在各模块里的硬编码通知、命令回复、错误提示。

所以干活顺序是：先确认 i18n 词典的**值**是否仍是英文（键存在不等于译了），
**再做一次硬编码串清点** —— 两步缺一不可，「有 locales」不能当作收工依据。

## 程序

1. **定面**。判据不是「源码里有没有英文」，而是**这段文本有没有被送到用户界面上**。
   日志、发给模型的提示词、正则、SQL、环境变量名全都不是文案。面的枚举关键词表见
   `references/sweep-recipe.md`（通知 / 命令回复 / 忙碌态 ack / 错误提示 / 平台适配器 / 卡片按钮 / 资源型文案）。
2. **AST 过滤**。只保留「可能送给用户」的字面量：`Return` 里的、包装进 `Reply(...)` 之类的、
   `append/extend` 到 `lines/parts/msg/text/note` 的、以及 **`send`/`notice`/`reply`/适配器发送方法的实参**。
   排除清单（docstring、`logger.*`、以 `[` 开头的机器标记、正则、键名…）见 references。
3. **并行翻译**。按文件切批，每批 2–6 个文件，**各批文件集必须互不相交**；
   指令模板与硬性规则见 references。文件不重叠时可让子代理直接改文件。
4. **验收三连**（父级独立做，**不采信子代理自述**）：
   ① AST 骨架比对 ② `py_compile` + 真实 `import` + **实跑格式化函数看输出** ③ 残留扫描。
5. **落地与生效**。把改动落成可重放的补丁/映射并写进重放包（升级会覆盖源码），
   然后**重启目标进程**；重启前先确认没有在跑的后台子代理。

## 验收三连（唯一可信的验收）

1. **AST 骨架比对**：pristine 与现状两侧把所有 `str` 常量归一成占位符，再 `ast.dump` / `ast.unparse` 对比。
   预期差异**只有**「中文没有单复数与首字母大写」导致的简化（`{n} hour/hours` 三元、
   `_plural()`、`.capitalize()` 消失）。除此之外的任何结构差异都按**夹带改动**逐条看。
2. **语法 + 导入 + 实跑**：`py_compile` 全部文件 → `importlib.import_module` 每个改动模块 →
   **真的调用**纯格式化函数（通知 / 状态 / 卡住提示）并把输出打印出来。
   只有这一步能抓到「半英半中」和「占位符错位」——编译通过完全不代表文案对。
3. **残留扫描判据按语料选**：纯英文语料（系统提示词）用「≥N 个连续英文单词」；
   混排语料（已有中文的短消息/通知/命令回复）必须用「**整串不含 CJK 字符**」。
   用英文单词计数扫混排语料会因 `Hermes`、产品名、工具名、URL 把全中文句子全部命中，
   实测假阳性数百条，真漏项被淹掉。

## 坑（每条都会真实浪费一轮）

1. **文案常有两层，只翻代码层等于没翻**：代码里的「回退短语表」可能被同目录的**资源文件**
   以 `replace` 模式整段覆盖，在用的那份是资源文件。先 grep 出实际加载路径与合并模式，再决定改哪层。
2. **多行隐式拼接的 f-string 必须以整段表达式为单位替换**：片段单独看往往不足 3 词而被漏掉，
   用户最终看到「半英半中」。只换其中一段 = 白干。
3. **`delegate_task` 的 `output_schema` 必须是合法 JSON Schema**，顶层 `type` 只能是
   `object` / `boolean`。一个 task 写成 `"type": "array"` 会让**整批**派发被拒、所有任务一个都没跑，
   必须整体重派。
4. **重启会连带杀掉同进程的后台子代理**，把它们停在「改了一半」的状态且结果永不回传。
   顺序永远是「子代理全部收工 → 重启 → 验收」；用户对重启时机有要求时也照此执行。
5. **文案一改，断言旧英文字面量的测试就会变红**：**不要为了让测试变绿去改测试**
   （用户明确反感），在报告里列出受影响的测试文件，让用户决定。
6. **别猜模块 API**：用 `dir(module)` 探明再调用（YAML 助手可能只有 `safe_load`，
   猜 `load_yaml_file` 会白跑一轮）。无 venv 的应用优先用自带**启动包装脚本**加载运行时依赖，
   别用系统 python（可能缺 ruamel / yaml）。
7. **报告要诚实完备**：写清改了哪些面、每文件处数、**刻意未翻的部分及原因**、受影响的测试。
   「编译通过 + 我翻了一批」不等于「用户看得见的英文清零」。

## 刻意保留英文（翻掉会坏功能）

- 机器解析标记：转向标记、`[SKILL_PRUNED]`、`[System note: ...]` 等以 `[` 开头的注入块
- 用于匹配 / 分类的串：平台错误特征、正则、`in` / `startswith` 的目标、映射键
- 工具名、参数名、枚举值、模型 / provider 名、配置键、环境变量名、路径、URL
- 上游按字面量比较的协议字段 / 按钮标识
