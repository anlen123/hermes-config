# 插件的运行期状态：快照、缓存、去重、对比基准

适用：用户要「记住上次查询结果」「和上次对比」「只推新增的」这类功能。骨架都一样 ——
一个 JSON 状态文件 + 原子写 + 降级读 + 对比后写回。SKILL.md 里是硬规则，这里是做法与验证细节。

## 文件位置与忽略

- 默认 `<仓库根>/data/<插件名>/<用途>.json`。`.gitignore` 已按 `/data/` 整目录忽略，
  但落地前 `git check-ignore -v <路径>` 确认一次 —— 仓库做过「纯代码库」重建，忽略规则改过。
- 允许 `.env` 覆盖路径时照这两个现成写法抄：`NOTE_STORAGE_PATH`（记事本）、
  `DEEPSEEK_BALANCE_HISTORY`（余额快照）。要点是 `config.py` 里给 `_DEFAULT_*` 常量，
  `load_config()` 返回 `"<用途>_path": Path`，相对路径按仓库根解析、`expanduser()` 展开 `~`。
- 空串视为「没配」，回落到默认路径；不要用空串当路径去 `mkdir`。

## 读写

```python
def save_snapshot(path: Path, snapshot: dict) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    tmp = path.with_name(path.name + ".tmp")
    tmp.write_text(json.dumps(snapshot, ensure_ascii=False, indent=2), encoding="utf-8")
    os.replace(tmp, path)
```

- 读：`FileNotFoundError` → 空表；**其余任何异常**（坏 JSON、权限、编码）→ 记一条 warning
  后返回空表。「没有历史」是一条合法状态，主流程必须能照常跑完并给出「首次查询」。
- 结构里同时放两个时间：`updated_at`（整卡/整批的写入时间）与每条记录的 `at`（该条数值的采集
  时间）。展示层要靠这两个时间分清「整批基准」和「这一行的基准」。
- 数值落盘前 `round(value, 4)`，避免浮点尾巴让 diff 与快照文件难看。

## 记录结构

- 按**业务键**记账，例如 `"DeepSeek|RMB"`、`"<群号>|<用户号>"`，不要按列表下标：
  上游接口增减条目、改名、顺序变化都不会串行。
- 每条是 `{"title": ..., "unit": ..., "balance": ..., "at": <时间戳>}` 这种自描述结构，
  不要把业务字段名硬编码进读取方。
- 本轮没取到值（查询失败、接口不给该字段）**不写入**，沿用旧记录 —— 失败一轮不会抹掉基准，
  下一轮成功仍算得出跨次差值。这一点要单独写个断言测：手工造「失败轮 → 成功轮」，
  断言差值等于两次成功值之差。

## 对比的语义

- 只有「本轮有值 + 上轮同一键有值」才算得出差值；其余情况不打标记。
- 差值展示分三态，别一个大而化之的「较上次」：

  | 情况 | 文案 |
  | --- | --- |
  | 有基准 | `↑ +1.23（+5.2%）`，变多绿、变少红、零变动灰 |
  | 没有基准 | `首次查询` |
  | 基准比整卡基准更早 | `↓ -0.90（较 09-27 12:53）`，写明用的是哪一次 |

- 百分比在上次值为 0 时省略（别除零）；差值小于半分钱按持平处理，别显示 `+0.00`。
- 分组/合计的增减**只在该组所有有值的行都能算出差值时**才显示，否则留空：
  口径不完整的合计数字比没有数字更误导。
- 对比只做展示，不能改变原有状态判定（预警线、状态色、是否推送）的语义。
- 基准口径（手动与定时是否共用）要在交付时向用户点明，并给出「各来源各算一份」的选项。
  别等他想起来问。

## 真踩过的坑

- **patch 工具的模糊匹配会弄乱 Python 缩进。** 在 bilibili_live/__init__.py 上连续 patch 时，多处插入块被匹配到错位缩进（字典字面量里出现 32 空格、TypedDict 字段错位），patch 报 success 但 py_compile 报 IndentationError。**每次 patch 后立即 `python -m py_compile <file>`；修法是再用 patch 把错块整块换成正确缩进，不要指望下一笔补丁自愈。**
- **接口返回空列表 ≠ 接口抛异常，但取「兜底」时要一起盖住。** bilibili_live 每小时播报的弹幕：`_fetch_data` 失败返回 None 时 `fetch_danmaku_with_user` 会返回空列表（不抛异常），所以兜底判断要写 `if not danmaku:`（空即兜底），只 try/except 会漏掉网络抖动场景（实测 16:15 播报就是这种：卡片空弹幕区，日志却有 warning）。兜底数据 = 会话里另存的**有序** `recent_danmaku`（去重集合 set 是无序的，取不了「最近 N 条」）。

## 跨重启续接：把在场次状态落盘

「重启机器人后，直播时长/统计不能归零」这类需求，靠内存里的 dict 做不到。

- 落盘位置固定 `data/<插件名>_state.json`（`data/` 已被 .gitignore 覆盖，不会入库）；
  用 `Path.cwd()` 拼（插件运行时当前目录就是仓库根）。
- **读写函数各自 try/except 兜底**：状态文件写失败绝不能把主流程（轮询/推送）带崩。
- 每条记录带 `live` 标记 + 全局 `saved_at`：
  - `live=True`（停机前还在直播）→ load 时把 `ended_at` 置为**落盘时间**，
    于是「重启耗时」自然计进续接窗口；窗口内重开播就续接，超窗口自动丢弃。
  - `live=False`（已下播的快照）→ 用记录里的真实 `ended_at`，过期直接丢。
- 落盘时机：轮询循环**每轮末尾**存一次（加最小间隔节流，如 20 秒），下播时 `force=True` 立即存。
- 大字段要限长（弹幕原文 2000 条、去重键 5000 个、排行榜前 300 人、采样点 2000 个），
  否则长直播会把文件写爆。
- 验证要**两个进程**：阶段一造状态并落盘；阶段二新进程启动（import 时 load）后断言
  起播时间沿袭、统计不归零、过期记录被丢弃。同进程内清空再试是假验证。
  ⚠️ 阶段一要显式 `live_session.clear()` —— 新进程 import 时已经把上一轮落盘读回内存，
  不清干净会「续接上一次测试的残留」，断言数字翻倍。

## 验证打法（四层，缺一不可）

1. **合成数据单测**：按文件路径 `importlib` 加载子模块（见 SKILL.md 「为什么不能用 import bot」
   一节），手工造两轮条目，断言差值、百分比、失败行无差值、失败轮不覆盖基准、坏 JSON 降级为空历史。
2. **渲染检查**：把图写成 PNG 落盘 → 打印格式/尺寸/字节数 → 用 `vision_analyze` 逐字读回。
   一次渲染里同时摆上「有基准 / 无基准 / 基准更早 / 失败行 / 零变动」，一张图看全所有分支。
3. **真实链路**：`scripts/probe_command.py` 跑真处理函数（真查接口），确认端到端连通。
4. **强制罕见分支**：把状态文件里的基准改成「2 小时前 + 数值减掉一个固定量」，再真跑一次 ——
   真实数值配必然出现的差值，同时证明分支连通和画法正确。

## Pillow 渲染的坐标账

- `textbbox` / `textlength` 可能返回浮点数；算出的画布高度/宽度先 `int()` 再给 `Image.new`。
- 行内新增元素（增减文字、角标）时，同一条横线上原有文字的 `_clip(...)` 上限要同步减掉新元素宽度
  加间距，并给个 `max(剩余, 最小值)` 兜底，否则新老两段会叠在一起。
- 会变长的页脚用现成的 `_wrap` 折行，按行数算卡片高度；不要去改原有文案来迁就一行放不下。
- 颜色沿用既有调色板常量（`C_GREEN_BAR` / `C_RED` / `C_DIM`），不要为「变多/变少」另造一套色值 ——
  同一张卡上出现两种语义相同的红，用户一眼能看出来。
