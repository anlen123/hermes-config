# 派子代理重构插件的派单模板

批量重构多个独立插件时用这套约束。可直接改写进 `delegate_task` 每个任务的 `context` 里。

## 为什么这样写

子代理对当前对话一无所知，且**倾向于扩大范围**——会顺手「优化」逻辑、改文案、加依赖。
把「不许做什么」写得比「要做什么」更具体，是唯一有效的约束方式。

## 派单模板

```
【环境】
仓库：<绝对路径>（nonebot2 机器人，跑在 Windows 上）
机器人运行的解释器：<Python313 绝对路径>（nonebot2 2.4.x、pydantic 2.x、httpx、Pillow、aiohttp 都已装好）
你负责：<插件目录>（约 N 个 .py 文件、共 M 行）

【本仓库已统一好的新风格范例，照着来】
<列出 2-3 个已经改好的文件路径>
（要点：模块顶部中文 docstring 说清这个文件干什么、命令怎么用；from __future__ import annotations；
完整类型标注；内部辅助函数 _ 前缀；模块级常量 UPPER_SNAKE 带注释；注释解释「为什么」而不是「是什么」；
异常窄化捕获并在吞掉处写明原因 + 日志；不留裸 pass、注释掉的死代码、未使用的 import/变量）

【必须保持不变，改了就算失败】
* 所有命令触发词 / 正则 / priority / block 设置
* 所有回复文案的含义与信息量（可以修错别字，不能删信息）
* 所有配置项名与其默认值
* 文件与目录位置、模块路径、插件加载名
* 任何被别处 import 的公开名字（函数/类/常量）

【要做的】
* 删掉从未被调用的函数、类、常量、import、变量；删掉注释掉的旧代码、调试输出、pass 占位；
  删掉空文件（删前先确认没人 import）
* 把重复出现的逻辑收成一个命名清晰的辅助函数
* 补全类型标注与中文 docstring

【绝对不要做】
* 不要动不属于你的文件（尤其别动 <显式列出 bot.py、.env*、共享工具目录、刚改好的核心插件目录>）
* 不要新增功能、不要改行为、不要顺手「优化」逻辑、不要新增第三方依赖
* 不要去动带嵌套 .git 的 vendored 插件，也**不要删掉那些 .git 目录**
  （会让仓库里的「子模块链接」悬空，见 SKILL.md 的踩坑）
* 不要 git commit / git add / git push

【验证，必须做完再回报】
1) 语法：<解释器路径> -m py_compile <你改过的每个 .py>
2) 加载自检：<解释器路径> <自检脚本绝对路径>
   重构前基线是「插件总数 N　成功 N　失败 0」，重构后必须一模一样；把实际的汇总行粘进回报里。
3) git diff --stat 确认你只改了自己负责的目录。

【回报】用中文，逐个插件说清：删了什么（函数/文件/行数）、合并了哪些重复逻辑、
有没有发现可疑但故意没动的东西、py_compile 与加载自检的真实结论、改动文件清单。
```

## 分组原则

- 按目录边界分组，**保证任意两个子代理的路径不重叠**。
- 大插件（>1000 行）单独一个；小插件（<200 行）可以 6-8 个归一个。
- 已停用/历史插件单独一组，并在派单里点明「它们可能残留 pydantic v1 写法」。

## 回报之后必须自己做的事

子代理的摘要**是自述，不是已验证的事实**。必须自己复跑一次自检脚本，
并用 `git diff --stat` 核对它真的只改了自己那一片。

子代理会大量声称「逐字节一致」「逐项对拍通过」。这类说法要自己复核一次，办法见下节。

## 行为等价的机器级证明

### 一、准备重构前的基线副本

把重构前的备份 zip 解到临时目录（`%TEMP%`），在**那个目录**里跑同一套脚本。
zip 里要含 `.env` / `.env.dev` / `.env.prod`，否则 `nonebot.init()` 起来的配置和真实环境不一致。

注意老版本的 `bot.py` 可能**没有 `PLUGINS` 元组**，是一堆散落的 `nonebot.load_plugin("…")` 调用；
脚本要能退回按调用顺序提取（`ast.walk` 遍历 `Call` 节点的 `.attr == "load_plugin"`）。

### 二、匹配器指纹对照

```
<Python313> scripts/dump_matchers.py <重构前副本> %TEMP%\before.json
<Python313> scripts/dump_matchers.py <仓库>       %TEMP%\after.json
<Python313> scripts/dump_matchers.py --compare %TEMP%\before.json %TEMP%\after.json
```

指纹 = 每个匹配器的「类型 / 优先级 / block / 权限 / 规则」。规则 repr 里的内存地址要先归一化。

### 三、集合顺序噪声（最容易把自己骗过去的一步）

下面三处内部都是**集合**，repr 顺序随进程变化，直接比会得到一堆假差异：

- `Permission(Dependent(call=_group), Dependent(call=_private))` —— 两个检查的顺序会互换；
- `Command(cmds=(('余额',), ('/ai余额',), …))` —— 命令项的顺序是集合迭代顺序；
- `Rule(Dependent(call=ToMe()), Dependent(call=Regex(...)))` —— 多个检查的顺序会互换。

规范化：权限里的 `call=X` 全部抽出排序；`Command(cmds=...)` 里的命令项抽出排序后重新拼串。

**判定噪声的硬办法：同一份代码连跑两次做对账。** 自己就会变的那些插件（本次是 love、
deepseek_balance）一律不算改动；规范化之后仍然稳定复现的差异才算真改动。
本次最终只剩两个有意改动：`bazaardb`（6 个匹配器合成 1 个）、`xuanran`（`^xr\s+` 放宽成 `^xr(\s|$)`）。

### 四、中文文案流失检查

用 AST 收集文件里所有含中日韩字符的字符串字面量，**排除 docstring**（否则重写文档会淹没信号）：

- 走 `ast.walk`，先记下 `Module` / `FunctionDef` / `AsyncFunctionDef` / `ClassDef` 的 `body[0]`
  若是 `Expr(Constant(str))` 就把它 `id()` 收进排除集合；
- 再收集所有 `Constant(str)` 且命中 `[\u4e00-\u9fff]` 的（跳过排除集合），按文件比对
  「重构前有、重构后没有」。

剩下的每一条都要能解释掉。本次 102 条全部落到这四类：
旧功能整体删除（用户批准）、整文件删除、logger 参数化 / `%s` 改 f-string、docstring 迁移。
拿不准的逐条去 `grep` 新代码确认文案还在（本次核了 jev_judge 的「正确/不正确」、jm 的 `%s` 文案、
seed_analyzer 拼装出来的正则等）。
